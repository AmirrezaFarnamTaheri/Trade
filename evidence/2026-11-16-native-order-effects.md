# Native venue-effect consumer

Source now connects a separate elevated `gym-submit` command to one reviewed LIMIT
order. It displays the current prepared ticket and requires an interactive exact
identity/version/runtime confirmation. It binds the pre-confirmation arm revision.
The native service rechecks the elevated Windows user/logon, prepared review,
native account sources, policy and owner evidence; no browser route can submit.

The request body comes from the durable ticket, not the caller. Hold admission and
BeginSend commit before WinHTTP receives a request. Native HTTPS pins the origin,
disables proxies, redirects, authentication negotiation, cookies and retries, and
checks stop, all source deadlines and owner-file evidence at the last send boundary.
A LIMIT request can spend only its reviewed fee-inclusive envelope. Each attempt
invalidates earlier balances and disarms; re-approval needs two fresh receipts.

A before-byte refusal abandons its identity and releases its hold. Any failure
after entering WinHTTP, unrecognized acknowledgement, HTTP error or interrupted
commit keeps the order uncertain and its hold intact. The helper never retries.
A real matching native order response is an observation, not settlement. A halt
cannot recall bytes already sent or cancel a venue order already accepted.

Synthetic tests exercise the actual admission/attempt/journal composition, a stop
during transport setup, before-byte/after-byte failures, malformed acknowledgements,
non-retry and restart preservation. Separate wire tests reject cross-version,
padding, identity and context mismatches. Publication scripts include the new
administrator-only helper; no service publication or installation was performed.

No real order was sent, no trade key was changed, and no owner evidence was created.
The next source branch reconciles native fill/terminal receipts with fresh balance
pairs before releasing holds. Installed-host and funded qualification remain pending.

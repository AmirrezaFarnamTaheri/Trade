# Whole-market research plan

**Decision this plan must support.** Given one account, a stated capital amount and the information available by each decision deadline, determine whether changing the portfolio improved realizable wealth after costs relative to feasible alternatives. A completed replay can support a negative or inconclusive research result. Qualification of the software, evidence for a particular strategy, and permission to send orders are separate decisions.

**Current starting point.** The November 14–21 development sweep observed 373 markets, qualified 342, traded 337 and had 318 quote-currency losses under the displayed-size model. Each market had independent capital. A two-market shared USDT replay ended at 964.39 from 1,000. These answer different questions and supply regression examples for different runners. Existing single-symbol jobs retain their recorded settings. The whole-market default below applies to the proposed project runner. [Earlier audit](../evidence/2026-11-22-historical-replay-financial-audit.md)

**Critical path.** Deliver the universe manifest and a hand-checkable cash ledger first, a deterministic spot replay second, and a full-week result with measured resource use third. Release additional product families independently when their lifecycle fixtures pass. Start comparative strategy research after the relevant replay path passes. The exploratory backlog is optional.

## Delivery and acceptance

### Common decision and accounting model

Build one snapshot per decision cutoff. Its numerical view has axes of decision time, instrument and feature. Each value carries units, availability time and a validity mask. Keep raw book events for matching, a directed graph of executable currency conversions for routing, and an account journal for cash, debt and positions. Sharing BTC as an underlying links two pairs for concentration limits; their order books and liquidity remain distinct. Give instruments stable identities through symbol changes and delistings.

Only events received by the cutoff enter the snapshot. Preserve evidenced sequence order within each source. Where clocks cannot resolve a cancel/fill race, replay the plausible outcomes and report their monetary difference. Freeze the entire cross-section before scoring. Resolve ties by an explicit stable rule. Removing a competitor can change targets; reversing the storage order of the same competitors must preserve them.

The archive command [whole_market_panel.py](../gym-core/scripts/whole_market_panel.py) writes a versioned JSONL header followed by one hashed feature slice per cutoff. The default is the whole point-in-time catalogue. Use `--symbols` for an explicit list or `--watchlist-id` for a pinned revision. When the watchlist lives outside the archive directory, pass its data root with `--watchlist-root`. Use `--venue` for another recorded namespace. The header binds the replay's spot eligibility intervals. Each row carries product flags, catalogue revision, observations, feature units through the header, receipt times and an explicit feature validity mask.

Shared-account portfolio runs and scheduled portfolio jobs can set `rank_gate` with `method` (`momentum` or `placebo`), `top_n_per_quote`, `min_breadth` and `seed`. At each fixed-duration bar close the gate freezes eligible active routes before the sessions reserve cash. The momentum score subtracts quoted spread from the preceding close-to-close midpoint return in the instrument's quote currency. The placebo draws from the same eligible pool within each currency. Breadth is the fraction of eligible markets with a positive return. Missing or stale quotes break the return chain. The gate screens new buys while sell and protection logic keep managing open positions. Saved runs include the two quote receipt times, scores, selection, breadth and blocked buy requests. #### Performance experiments

The first benchmark deliverable runs one small immutable project from submission through reconciled report publication. Record an ordered financial digest, eligible and skipped counts, query count and work completed. This bridges the existing arithmetic benchmark and collector load tests. Limit paired timing runs to changes touching the measured path.

| Order and owner | Experiment | Evidence required to keep the change |
|---|---|---|
| 1. Collector and operations | Run the existing full-frame, hour-rotation and market-API fixture with replay idle and under increasing worker counts. Capture received/written counts, publication and event-loop lag, request latency, SQLite busy waits and WAL size. | Select the fastest research configuration that preserves every expected receipt and meets existing latency checks. Keep workload and rotation times fixed. |
| 2. Portfolio engine | Replace only the materialized per-symbol tuple lists passed to the chronological merge with iterators. A 100-stream, 200,000-event synthetic comparison measured median additional traced memory of 19.81 MiB eager versus 0.05 MiB lazy over three runs each. | Compare the full ordered stream including equal timestamps, then checkpoint/resume, postings and output identities. Measure process-tree peak memory on the complete replay. Account separately for parsed input and retained results before revising observation limits. |
| 3. Database and API | Trace market-products enumeration and per-symbol metadata queries in services/capabilities.py. Compare an indexed, set-based as-of lookup on an immutable catalogue snapshot. | Record query count, query plan, read-transaction duration and request p95. Match symbol order, missing metadata and as-of boundaries. Measure collector impact before adding an index. |
| 4. Browser | Trace filter input through sorting, rendering and paint for 373 market rows under EN/FA, on desktop and narrow screens. Isolate time spent in sorting versus DOM updates before choosing a fix. | Compare input-to-next-paint distributions and long tasks on identical input sequences. Preserve focus, row order and accessible result updates. |
| 5. Reporting | The existing synthetic arithmetic benchmark on Windows CPython 3.11.9 measured medians of 2.12, 7.15 and 20.65 ms for 1,000, 3,000 and 6,000 decisions on November 22 (five repetitions). | Profile the complete report request including SQLite reads, serialization and response size before optimizing arithmetic. |

Use an immutable seed snapshot and fresh output directory for each timed run. Publish raw samples with hardware, interpreter, concurrency, cold/warm conditions, output comparison and final disposition. Start CI with exact receipt/order invariants and a small paired timing trend. Repeat regressions before treating shared-runner wall time as a failure. Run expensive whole-week and collector-contention comparisons on a stable host.

The archived market-products comparison returned identical ordered reports for all 373 observed symbols at the same cutoff, including missing metadata. The indexed query reduced the read statement count from 747 to one. Across five requests per version, the nearest-rank 95th percentile fell from 4,113 ms to 22 ms. These were service-level measurements on a read-only archive with statement tracing and a concurrent replay worker.

The historical catalogue's latest-receipt lookup now uses the existing book index to seek each instrument key and its newest receipt within the requested bounds. Six paired read-only lookups across three archived day windows returned identical instrument and timestamp rows. Median lookup time fell from 2,763.36 ms to 7.00 ms. This measures one lookup, with the filesystem cache left intact.

On a three-hour archive slice across all 373 markets, repeated USDTTMN closure checks took 22.3 of 65.4 profiled seconds. Portfolio valuation now reuses the closure intervals for the current Tehran date and recorded rule revision. The original half-open boundaries, overnight windows and intraday rule changes still apply. In three serial unprofiled runs per version against the same archive slice, baseline times were 30.83, 30.66 and 30.27 seconds. Cached times were 17.97, 18.47 and 18.31 seconds. All six runs covered 391,419 observations and matched the full canonical artifact.

One serial full-week comparison on the same Windows archive measured 904.58 seconds with the old closure lookup and 456.97 seconds with the cached lookup, a 49.5% reduction. The cache was tested first, with the filesystem cache left intact. Both workers processed 10,146,017 observations and produced identical canonical artifacts for the 373-market run `eb61e7f0dd58d54e`, with digest `ffe9cc726db6ce28`. The matching artifact includes all fills, account postings, balances and coverage. Sampled aggregate worker process-tree RSS was 449.3 MiB before and 447.6 MiB after.

The six-hour archived replay profile attributed 32.9 of 104.1 seconds to building the input digest. Best-level replays now project only the receipt and quote fields that enter that digest after the event loop has validated the same read snapshot. A separate stage comparison over 803,405 observations measured medians of 17.27 seconds before and 11.03 seconds after across two runs per version. All four matched the same input digest. Depth-aware runs continue to hash full book levels. The regression fixture compares the projected digest with the original decoder for duplicate receipts, exact decimal text, missing quantities and repeated flags.

A single paired full-week calculation on Windows measured 798.03 seconds with the original digest pass and 696.83 seconds with the projection, a 12.7% reduction. Both replays processed 10,146,017 observations across 373 markets and matched the complete canonical artifact for run `eb61e7f0dd58d54e`. The faster implementation ran first. The filesystem cache was left intact, and a focused test overlapped its start. Sampled process-tree peak RSS rose from 447.9 to 460.5 MiB in this pair.

The next three-hour profile spent 10.2 of 52.6 seconds building the input digest and 9.6 seconds decoding book events. The replay now encodes up to 256 records per digest update and reuses decoded receipt times, flags and canonical decimal text through bounded caches. The compatibility test crosses the batch boundary in both best-level and depth-aware replays, including repeated receipts, a legacy timestamp format and exact decimal text.

The hour-rotation fixture now compares zero and two concurrent market-product readers against the same collector database. Each case preserved 5,968 book records, 5,968 trade records and both raw segments with verified hashes and contiguous sequences. On the November 22 repeat, both reported 6 ms event-loop p99 and about 4.0 MiB sampled peak WAL. The existing market API peaked at 83.5 ms with zero readers and 104.0 ms with two readers. One earlier run overlapped an 11 GB archive copy and breached the separate tick-latency bound at 2,016 ms p99. The repeat measured 76.9 ms. These fixtures exercise the on-host collector and read contention. Dedicated measurements by long-running replay worker count and SQLite busy-wait timing remain open.

During the fifth 373-market scheduler benchmark repeat, the combined Windows suite also ran the rotation fixture. The zero-reader case preserved every observation and both raw segments, with one 2,307 ms frame exceeding the one-second bound. The focused rerun while the same replay was active passed both reader cases. Maximum frame times were 73.5 and 15.9 ms, and market API maxima were 76.6 and 74.6 ms. This records the observed spike and successful repeat under overlapping work. Its cause and a controlled worker-count limit remain unverified.
